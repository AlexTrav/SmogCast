# backend – API SmogCast

FastAPI только читает базу Neon, которую каждый час пополняет GitHub Actions
(`data hourly` – ряд и снимки прогнозов, `model live` – прогнозы всех моделей). API ничего не пишет
и не обучает – он отдаёт сайту готовые данные в JSON. Единственный расчёт на сервере – кнопка
«Пересчитать сейчас»: быстрые модели заново от того же часа ряда (см. ниже).

```bash
make run        # API на http://localhost:8000, документация – http://localhost:8000/docs
make test       # автотесты на временном Postgres 18 в docker compose
make readonly   # один раз: пользователь базы только для чтения -> SmogCast/.env.api
```

## Точки API

Время – UTC в ISO 8601 (`2026-10-31T15:00:00Z`), концентрации – мкг/м³. Ряды отдаются компактно:
`start`, шаг `step` и массивы значений подряд; пропущенный час – `null`.

| Адрес | Что отдаёт |
|---|---|
| `GET /api/health` | `{"status":"ok"}` – жив ли сервер; базу не трогает |
| `GET /api/status` | последний час ряда: PM2.5, PM10, индекс US AQI и уровень, изменение за 24 ч, последние запуски сбора и моделей, модель по умолчанию |
| `GET /api/forecast?model=` | последний прогноз на 72 ч: `pred`, интервалы `lo80/hi80`, `lo95/hi95`, прогноз самой CAMS `cams`; без `model` – смесь по умолчанию, список моделей – в `models` |
| `GET /api/history?step=&from=&to=&fields=` | ряд по часам (`step=hour`) или по суткам (`day`, по умолчанию: `mean`, `max` и число часов в сутках); `from`, `to` – дни по местному времени Алматы, без них – весь ряд с 01.09.2022; `fields` – до 4 колонок ряда (по умолчанию `pm2_5`) |
| `GET /api/verify?days=7` | журнал «прогноз → факт» по живым прогнозам за 1–30 последних суток: MAE каждой модели и самой CAMS (`cams` – её прогноз, известный в момент выпуска нашего) всего, по горизонтам 1–24, 25–48, 49–72 ч и по суткам («гонка моделей»); `yesterday` – прогноз модели по умолчанию, выпущенный сутки назад, рядом с фактом |
| `GET /api/weather` | прогноз погоды ECMWF IFS на 72 ч (температура, влажность, точка росы, ветер км/ч и откуда дует, давление, осадки, облачность) и факторы смога на ближайшие сутки: `cold` (средняя < 0 °C), `calm` (ветер < 3 км/ч), `dry` (осадков < 0,1 мм), `heating` (отопительный сезон 15.10–15.04) |
| `GET /api/region` | сетка 5x5 узлов CAMS вокруг Алматы для карты: сутки назад и 3 суток вперёд, массивы `[час][широта][долгота]` для PM2.5, PM10, ветра и его направления |
| `GET /api/explain` | «почему такой прогноз»: последний прогноз Prophet как произведение уровня (`level`, мкг/м³) на множители суточного (`daily`) и годового (`yearly`) хода, в `summary` – когда в сутках минимум и пик; из каких моделей сложена смесь по умолчанию (`blend`); во сколько раз прогноз погоды сдвигает LSTM (`weather.ratio` – LSTM с погодой / без неё) |
| `GET /api/models` | итоги честной проверки из `model/reports/final`: рейтинг на валидации (`selection`) и все метрики на тестовом году (`test`) – MAE по горизонтам, интервалы, уровни AQI, тест Диболда–Мариано, пример прогноза |
| `POST /api/recompute` | «Пересчитать сейчас»: сезонно-наивная, профиль за неделю, LSTM и LSTM с погодой (ONNX) заново от последнего часа ряда; время каждой модели (`ms`), прогноз на 72 ч и наибольшее отличие от ежечасного расчёта того же часа (`diff`); смесь по умолчанию – с ARIMA из ежечасного расчёта. Не чаще раза в 30 с с адреса (иначе 429, `retry_after` в теле), один пересчёт одновременно, повторное нажатие в тот же час – готовый ответ (`cached: true`) |
| `GET /api/performance?hours=48` | производительность: длительность последних ежечасных запусков сбора и моделей, время каждой модели, задержка данных источника, размер базы, сколько часов за неделю прошли с запуском; `api` – время работы сервера и скорость ответов каждой точки (p50, p95, сколько ответов 304) |

Пороги факторов смога взяты из исследования ([research/](../research/README.md)): смог сильнее всего
связан с холодом, осадки его смывают, а ветер в ряду слабый, и выделяется только почти полный штиль.

Уровни US AQI (EPA, 2024): `good` ≤ 9,0; `moderate` ≤ 35,4; `sensitive` ≤ 55,4;
`unhealthy` ≤ 125,4; `very_unhealthy` ≤ 225,4; `hazardous` – выше.

## Как устроено «реальное время»

- Данные меняются раз в час (задача стартует в xx:17 UTC). Сайт раз в минуту спрашивает
  `/api/status` с заголовком `If-None-Match`; пока нового часа нет, ответ – пустой `304`.
- Каждый ответ считается один раз на версию данных (последний час ряда и номера последних
  запусков) и до следующего обновления берётся из памяти: повторный запрос – миллисекунды.
  Версию API спрашивает у базы не чаще раза в 30 секунд (`VERSION_TTL`).
- У каждого ответа есть заголовок `Server-Timing` – время его расчёта на сервере (видно в DevTools).
- Ответы сжимаются gzip: весь почасовой ряд (36,5 тыс. часов) – около 50 КБ.
- Соединения с базой закрываются через минуту простоя, а `/api/health` базу не трогает: бесплатная
  Neon засыпает, когда сайт никто не открывает, и просыпается на первом запросе (около 1–3 с).

## Пользователь базы только для чтения

API подключается не владельцем базы, а ролью `smogcast_api` (`make readonly`, скрипт
[readonly.py](readonly.py)): у неё есть только `select` на все таблицы, включая будущие, а сессии
открываются в режиме только чтения с ограничением запроса 15 с. Даже если адрес API найдут,
изменить базу через него нельзя. Пароль генерируется в контейнере и сразу пишется в `SmogCast/.env.api`
(в git не попадает); повторный `make readonly` меняет пароль. `make run` берёт строку подключения
из `.env.api`, а пока его нет – из `.env`.

## Выкладка на Render

Сервис описан в [render.yaml](../render.yaml): бесплатный план, Франкфурт (рядом с Neon), сборка
по `backend/Dockerfile` из корня репозитория, проверка `/api/health`, автодеплой при коммите,
затрагивающем API или отчёты моделей. `DATABASE_URL` – строка из `SmogCast/.env.api`, Render
спрашивает её один раз при создании сервиса.

Бесплатный сервер Render засыпает после 15 минут без запросов и просыпается на первом запросе
(около минуты) – так бесплатные часы тратятся, только пока сайтом пользуются. Сайт при открытии сразу
будит API запросом `/api/health` и, пока сервер просыпается, показывает заготовки блоков.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения к базе (на сервере – пользователь только для чтения) |
| `CORS_ORIGINS` | адреса сайта через запятую, по умолчанию `*` |
| `VERSION_TTL` | как часто проверять новые данные, с (по умолчанию 30) |
| `PORT` | порт (его задаёт Render), по умолчанию 8000 |

Образ собирается из корня репозитория (`docker build -f backend/Dockerfile .`): кроме кода API в него
идут отчёты моделей `model/reports` (модель по умолчанию) и быстрые модели для пересчёта –
[model/light.py](../model/light.py) с тем, что он импортирует, и обученные LSTM `model/artifacts/live`.
Код моделей один и тот же у ежечасной задачи и у API, поэтому пересчёт совпадает с ежечасным расчётом.
pandas и onnxruntime загружаются только при первом пересчёте, чтобы сервер быстрее просыпался.
