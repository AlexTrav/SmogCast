# SmogCast – данные

Почасовой ряд концентрации PM2.5 и погоды в Алматы с 01.09.2022 по текущий час –
[series/almaty.csv](series/almaty.csv) (около 36 тыс. часов, 2,7 МБ). Ряд хранится в репозитории
и дописывается скриптом сбора.

## Сбор и проверка

Всё запускается в Docker, локальное окружение Python не нужно:

```bash
make update   # дописать свежие часы (последние 7 дней перезапрашиваются) и проверить ряд
make full     # выгрузить весь ряд заново
make check    # только проверить ряд
make test     # pytest сбора и проверки (без обращения к сети)
```

Повторный запуск в тот же час ничего не меняет: выгрузка воспроизводима.

## Источники

| Колонки | Источник | Что это |
|---|---|---|
| `pm2_5`, `pm10`, `no2`, `co`, `so2`, `dust` (мкг/м³) | [Open-Meteo Air Quality API](https://open-meteo.com/en/docs/air-quality-api), домен `cams_global` | расчёт модели CAMS (Copernicus Atmosphere Monitoring Service), сетка 0,4° (около 45 км), узел 43,3° с. ш., 76,9° в. д. |
| `temp`, `dew` (°C), `rh`, `cloud` (%), `wind` (км/ч), `wind_dir` (°), `pressure` (гПа), `precip` (мм) | [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api), модель `best_match` | оперативная модель ECMWF IFS: по значениям `best_match` для Алматы совпадает с `ecmwf_ifs` за весь период |

Ключи API не нужны. Данные распространяются по лицензии
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/): «Air quality data: CAMS / Copernicus,
weather data: ECMWF IFS, via [Open-Meteo.com](https://open-meteo.com/)».

## Как устроен сбор

- Время – в UTC (`2022-09-01T00:00Z`). Местное время Алматы с 01.03.2024 – UTC+5, до этого было UTC+6,
  поэтому в местном времени шкала «прыгает»; переводить в местное время будем только для графиков и признаков.
- Запросы – не больше года за раз, с повтором при обрыве соединения или ответе 5xx/429.
- Часы после текущего отбрасываются: API отдаёт их как прогноз, а нужен ряд «по факту».
- Значения последних дней могут уточняться следующими прогонами моделей, поэтому обновление
  перезапрашивает последние 7 дней. Последние часы, где один из источников ещё
  не отдал значение, отбрасываются до следующего обновления.
- Отрицательные концентрации (у пыли в CAMS встречается –1) обрезаются до 0.
- Проверка (`collect/check.py`): ряд начинается 01.09.2022, шкала почасовая без разрывов и повторов,
  нет пропусков, значения в допустимых диапазонах (`RANGES` в `collect/config.py`).

## Ограничения

- **Это не замеры датчиков, а оценка модели CAMS.** Сетка около 45 км усредняет город с горами
  и пригородами, поэтому локальные пики смога в низинах города модель, скорее всего, занижает.
  Прогнозная система учится предсказывать именно эту оценку.
- **Архива прошлых прогнозов CAMS нет**: API принимает переменные `pm2_5_previous_dayN`, но
  возвращает пустые значения. Сравнить свои модели с прогнозом CAMS можно, только если сохранять
  его прогнозы самостоятельно, начиная с текущего момента.
- **Высота пограничного слоя не используется**, хотя важна для инверсий: в архиве ERA5 у Open-Meteo
  она есть только до 31.12.2023, в архиве оперативных прогнозов – с 01.09.2024, между ними дыра в 8 месяцев.
- CAMS global начинается в августе 2022, поэтому в ряду четыре отопительных сезона – мало для
  уверенной оценки годовой сезонности.
- **Ряд неоднороден**: внутри него три обновления модели CAMS (27.06.2023, 12.11.2024, 12.05.2026)
  с заметными сдвигами уровня загрязнителей, а ветер IFS по годам «проседает» относительно реанализа ERA5;
  есть и один сбой CAMS – 60 часов в декабре 2022 без антропогенных выбросов. Ряд здесь хранится
  как есть, разбор и обработка – в [research/](../research/README.md).
